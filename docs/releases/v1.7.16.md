# HOME NET 1.7.16 — исправление определения WAN в мониторинге

## Причина

10 ноября 2026 г. на резервном квартирном Cudy (OpenWrt 25.12.5, WAN Dom.ru) после обновления до 1.7.15 кратковременно был ошибочно записан `VPN BYPASS DETECTED`, `Health: FAIL`: неопределённый по интерфейсу запрос к внешнему IP-сервису проходил через AWG, поэтому `WAN_IP` ошибочно становился равен внешнему IP VPN. При привязке к физическому `eth0` запрос возвращал IP провайдера. Следующая проверка восстановила `Health: OK`.

## Изменения

- Monitoring 1.7.10: `podkop-country-lookup --ip --wan` и `--wan` получают `l3_device` из `ubus call network.interface.wan status` через `jsonfilter` и выполняют проверки с `curl --interface <wan-device>`.
- При невалидном или отсутствующем WAN-интерфейсе внешний запрос без привязки запрещён, результат становится UNKNOWN, а не ложным VPN bypass.
- При реальном совпадении внешнего WAN IP и IP VPN причина `VPN BYPASS DETECTED` сохраняется в `REASON` файла health-state.
- Тесты воспроизводят VPN-маршрутизацию обычного HTTPS, корректную физическую привязку и отсутствие небезопасного fallback на OpenWrt 24.10.4 и 25.12.5.

## Состав пакета и целостность

- Bundle: `1.7.16`, Monitoring: `1.7.10`, Failover: `1.5.0` (без изменений).
- Native agent **остаётся v1.7.15**: исходный commit `f8031fa7ee2f6cb66d0a10677d8bf913a140adaf`; проверенный опубликованный архив `home-net-native-agent-1.7.15-linux-arm64.tar.gz`, SHA-256 `74eea3ebeac16a41f2a61ea8581b022b807f14d86756c1e38d61fb090c96e9f0`. Новый native binary не компилировался: изменение только в shell-мониторинге.
- Native bootstrap исходный commit `d68644275a09efced402a9e289f6ea5c89ff7d84`; SHA-256 `ee071c08bedccab75ccc568c4b03c1ddf6238c68f73a42686e6601c4d841badc`.
- Monitoring 1.7.10 source ref `755c581586337435e6792f326092e3d525f4c041`.
- Используются immutable versioned tag и проверка SHA-256. Автообновление не разрешено: `DEFAULT_AUTO_UPDATE_MODE='check'`, политика rollout остаётся `manual`.
