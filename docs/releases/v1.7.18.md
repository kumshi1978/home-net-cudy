# HOME NET v1.7.18 — безопасное обновление при подготовленном VPN-резерве

## Сценарий
На основном квартирном Cudy (`apartment-main`) после доставки нового резервного VDS осталась транзакция `prepared` с идентификатором `1d40d2f70e92f42d9bfa87c2967a525a`, основным выбранным `awg_main` и подготовленным `awg_backup`. Установщик v1.7.17 не обновляет контроллер при `prepared`, а старый контроллер требует GeoIP `US`, хотя сервер определён как `DE`.

## Изменения
- Только native installer получает явный opt-in `HOME_NET_ALLOW_PREPARED_UPGRADE=1` плюс `HOME_NET_PREPARED_DEPLOYMENT_ID=<32 hex>`.
- Проверка в общей maintenance-блокировке: точный ID транзакции, текущий boot-id, `phase=prepared`, исходный `awg_main`, целевой `awg_backup`, валидная справочная страна, активный интерфейс Podkop `awg_main`, неизменный SHA-256 `awg showconf awg_backup` относительно ранее зафиксированного `candidate.sha256`.
- При отсутствии opt-in, ошибке ID, перезагрузке, смене активного пути или отпечатка сохранён прежний отказ.
- Инсталляция **не** переводит фазу автоматически, не пишет ключи и маршруты VPN, не вызывает `verify`, `accept` или `rollback`. Сохранение происходит только отдельной штатной командой на новом контроллере после повторной проверки фактического IP выхода.
- Как и прежде, backup файлов кода делается приватно до обновления, на сбое установщика старая версия восстанавливается.

## Порядок canary
1. Не перезагружать `apartment-main` с `prepared`; подтвердить текущую загрузку, ID, активный `awg_main`, живой `awg_backup` и endpoint.
2. Выполнить контролируемое обновление native до 1.7.18 с opt-in и точным ID. Зафиксировать успешный preflight и контрольные суммы пакета.
3. Убедиться, что `prepared` остался неизменным; через `home-net-vpn-router verify` получить `verified`, затем через панель подтвердить `accept_verified` и проверить `completed/<ID>/phase=accepted`.
4. Только после успешного canary рассматривать остальные устройства.

## Развёртывание и откат
`rollout=manual`, автообновление остаётся в режиме check. Публикация GitHub Release не выполняет установку на Cudy. **Перед запуском на рабочем роутере нужен отдельно проверенный способ передачи opt-in переменных в native installer**, иначе подготовленная транзакция корректно заблокирует обновление.
