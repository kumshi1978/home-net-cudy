# HOME NET 1.7.21 — квартирный резервный Cudy, контролируемый candidate

**Status: draft canary; not a published/fleet release.** Scope: only apartment-backup Cudy (Dom.ru, OpenWrt 25.12.5). The apartment-main (MGTS) and both dacha routers must not be touched; no production VDS/clients must be changed by this rescue.

## Why
On the backup Cudy the pending deployment `0fa6ae7e36eb94f8417244cc0eddf577` has phase `prepared` and metadata:
- source/selected VPN: `awg_backup`
- candidate: `awg_main`
- advisory country: `DE`

HOME NET 1.7.20 native installer assumed the opposite direction and failed with `prepared transaction targets unexpected VPN slots`. Version 1.7.21 accepts both directions **without relaxing identity, same-boot, source/Podkop selection, lock or candidate fingerprint checks**. Preflight/install only upgrade native code and preserve the pending transaction, network, Podkop and failover routes. It is **not** a mechanism to erase an unknown transaction or switch VDS automatically.

## Hardware preflight (read-only with respect to persistent VPN settings)
Before any installer invocation, on **apartment-backup only**, check:

```sh
set -eu
T=/etc/home-net/vpn/transaction
test "$(cat "$T/phase")" = prepared
test "$(cat "$T/deployment-id")" = 0fa6ae7e36eb94f8417244cc0eddf577
test "$(cat "$T/boot-id")" = "$(cat /proc/sys/kernel/random/boot_id)"
test "$(sed -n '1p' "$T/metadata")" = awg_backup
test "$(sed -n '2p' "$T/metadata")" = awg_main
test "$(uci -q get podkop.main.interface)" = awg_backup
printf '%s\n' '=== SHA of candidate configuration only ==='
awg showconf awg_main | sha256sum
cat "$T/backup/candidate.sha256"
```

**Do not print `awg showconf` without the pipe**, and do not print private keys. Candidate SHA and saved candidate fingerprint must match; if they differ, stop and diagnose. If the router rebooted after the recorded boot ID, stop: this recovery path deliberately rejects a previous-boot prepared transaction. Verify operator has local management reachability independently of the VPN and backup copy of router settings before installing.

## Canary package preflight
```sh
ARCHIVE=/tmp/home-net-native-agent-1.7.21-linux-arm64.tar.gz
echo '9131f96fb1df90622fe4d21b007294652c4406ecf46f51774d6302a54663109d  /tmp/home-net-native-agent-1.7.21-linux-arm64.tar.gz' | sha256sum -c -
mkdir -p /tmp/home-net-native-canary
tar -xzf "$ARCHIVE" -C /tmp/home-net-native-canary
cd /tmp/home-net-native-canary/native-agent-arm64
sha256sum -c SHA256SUMS
HOME_NET_ALLOW_PREPARED_UPGRADE=1 HOME_NET_PREPARED_DEPLOYMENT_ID=0fa6ae7e36eb94f8417244cc0eddf577 sh ./install.sh --preflight
```

This preflight does not change VPN configurations or routes; it validates locks, transaction, candidate fingerprint, native code and current flash space. **Do not proceed if preflight reports any error.**

## Controlled installation gate
Only after PASS of the full CI pipeline and the above on-router preflight, under explicit backup-only operator confirmation, use the already verified unpacked candidate directory:

```sh
cd /tmp/home-net-native-canary/native-agent-arm64
HOME_NET_ALLOW_PREPARED_UPGRADE=1 HOME_NET_PREPARED_DEPLOYMENT_ID=0fa6ae7e36eb94f8417244cc0eddf577 sh ./install.sh --install
/usr/sbin/vpn-control-cudy version
cat /etc/home-net/vpn/transaction/phase
uci -q get podkop.main.interface
```

Expected: native version starts with `1.7.21`, transaction stays `prepared`, Podkop remains on `awg_backup`. **This command is not yet authorized for execution on hardware by CI alone**. It replaces native code only; it does not automatically complete the transaction or install every component of bundle 1.7.21. The GitHub tag/release URL is intentionally not published.

Next: separately verify/accept or recover the pending transaction under reviewed controller semantics, observe panel reconciliation and actual VPN egress, test failure/rollback, then reboot the backup Cudy under a separate maintenance window. Only when backup internet, panel polling, restart persistence and failover are confirmed should the primary be evaluated.
