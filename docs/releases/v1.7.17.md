# HOME NET 1.7.17 — GeoIP справочно, VPN проверяется фактическим выходом

## Причина
При смене резервного VDS страну адреса `83.141.77.226` панель сначала определила как US, затем как DE. На `apartment-backup` новая доставка `62ac12b3...` прошла `verified`, но при `accept_verified` контроллер сравнивал текущую GeoIP страну с `US` из transaction/metadata, выдавая `recovery_required`. Работающий профиль не сохранялся.

## Исправление
- Убрано сравнение GeoIP-страны из обязательной проверки кандидата `probe` в `home-net-vpn-cudy-adapter`.
- Сохранены обязательные проверки: конкретный интерфейс `curl --interface if!awg_*`, IPv4 выхода, endpoint `awg show ... endpoints`, **выходной IP равен IP назначенного VDS**, новый handshake после staging, доступность Podkop/sing-box, безопасный активный путь и транзакционный откат.
- Страна в протоколе остаётся информационной; поле `country` сохраняется для совместимости со старыми заданиями. Существующая транзакция `verified` с US должна пройти `accept-id` без пересоздания ключа, если текущий egress и handshake подтверждены.
- Отказ при фактическом отличии egress от endpoint. Это намеренное требование для HOME NET: **для VDS с отдельным NAT exit IP требуется отдельный явный дизайн**, не обход проверки.

## Проверки
- `tests/test-vpn-cudy-adapter.sh`: неверная страна FR не блокирует корректный VPN; GeoIP провайдер не вызывается; неверный egress IP отклоняется.
- `tests/test-vpn-router.sh`, Go native agent `go test -race`, `go vet`, native ARM64 сборка, installer preflight и полный CI.
- Hardware canary: сначала квартирный резервный Cudy с текущей транзакцией `verified`, затем квартирный основной. **Никакого автоматического fleet rollout.**

## Приёмка на оборудовании
1. Сохранить резервные копии состояния транзакции и `/etc/config/network`.
2. Обновить только контроллер/агент из проверенного пакета, с SHA-256 и собственным snapshot, сохранив действующий `awg_main`.
3. В панели «Роутеры» выбрать «Сохранить проверенный резерв» для существующей транзакции без нового задания на выдачу профиля.
4. Убедиться: `TRANSACTION_STATE='idle'`, в `completed/<deployment-id>/phase` — `accepted`, `awg_backup` остаётся на новом VDS, `awg_main` не меняется, после перезапуска контроллера постоянная конфигурация соответствует целевому endpoint.
5. Только затем отвязывать старый VDS в панели v0.4.2 после свежего отчёта Cudy.

## Ограничения
Публикация пакета не устанавливает его на роутер. Native installer разрешает обновление только в `idle`/`verified` и не должен изменять сетевые маршруты; на `prepared` автоматическое обновление запрещено. `rollout-policy` остаётся manual.
