# HOME NET v1.7.19 — восстановление обновления при prepared

## Причина
На квартирном основном Cudy `root@Cudy` транзакция `1d40d2f70e92f42d9bfa87c2967a525a` оставалась `prepared`. HOME NET v1.7.18 уже содержал строгий opt-in в native installer, но общий `install-all.sh` завершался **до** native preflight с `ERROR: unfinished VPN transaction requires review before update`. Поэтому обновление через LuCI отклонялось без изменения версии.

## Изменения
- При обычном обновлении все прежние запреты для `prepared` остаются в силе.
- Только в v1.7.19 и при `HOME_NET_UPDATE_IN_PROGRESS=1` доступен отдельный **native-only** путь: требуется переданный оператором `HOME_NET_ALLOW_PREPARED_UPGRADE=1` и точный 32-hex `HOME_NET_PREPARED_DEPLOYMENT_ID`.
- При автоматическом обновлении (`HOME_NET_AUTOMATIC_CONTEXT=1`), через LuCI (`HOME_NET_MANAGEMENT_CONTEXT=1`), без явно указанного ID и без согласованного состояния операция не разрешается.
- Общий установщик захватывает тот же maintenance lock, проверяет ID и вызывает только зафиксированный по SHA-256 native bootstrap (preflight и install), затем завершается **до** установки Failover, Monitoring, Podkop, updater и других компонентов.
- Native 1.7.18 проверяет ту же загрузку, фазу `prepared`, active `awg_main`, target `awg_backup`, неизменный SHA-256 `awg showconf awg_backup`. Внутри установки работает rollback кода при ошибке.
- `phase`, ключи, сетевые маршруты и выбор основного VPN не меняются. Новый контроллер потом отдельно выполняет `verify` и `accept-id`.

## Совместимость и регламент
Native 1.7.18 ARM64 переиспользован без пересборки из прежнего immutable источника `755e602131a3eba76d4e513678fd2b006245c504` и SHA-256 `3c08ef151b0ad7113f157e329bde2607480610219f068b4b26cc0c6f10f3d80e`. Изменён только новый пакет HOME NET v1.7.19. Rollout остаётся `manual`, автообновление и запуск из LuCI не выполняют rescue.

Перед ручной установкой на квартирном `root@Cudy`: убедиться, что исходный `awg_main` работает, целевой `awg_backup` отвечает, boot-id совпадает с transaction/boot-id, а ID транзакции равен `1d40d2f70e92f42d9bfa87c2967a525a`. Рекомендуется доступ к консоли/локальному роутеру на случай сбоя.

Запуск по SSH от root, без сохранения опций в конфигурации и без изменения автоматики:

```sh
HOME_NET_ALLOW_PREPARED_UPGRADE=1 \
HOME_NET_PREPARED_DEPLOYMENT_ID=1d40d2f70e92f42d9bfa87c2967a525a \
HOME_NET_CONFIRMED_RELEASE=v1.7.19 \
/usr/bin/home-net-update apply
```

После успешного ответа: проверить `/usr/sbin/vpn-control-cudy version`, `/usr/bin/home-net-vpn-router status`, `uci -q get podkop.main.interface`, затем отдельно выполнить `/usr/bin/home-net-vpn-router verify`. Только после `verified` сохранять профиль через панель и проверять `completed/<ID>/phase=accepted`. При любом отказе **не** редактировать `metadata` и не удалять каталог транзакции.

## Проверки
`tests/test-prepared-recovery-bundle.sh` проверяет отказ без opt-in, по неверному ID, из automatic/LuCI контекста, а при правильных флагах — только вызов native preflight/install без скачивания сторонних компонентов. Native `test-install.sh` независимо проверяет ошибочные boot-id, fingerprint, ID и неизменность сети. Публикация требует CI, immutable pin, checksums, без deployment на физические роутеры.

## Откат
Если установка native прервана, восстановление старых файлов выполняет native installer. После ошибки прекратить rollout, собрать диагностические журналы; не форсировать транзакцию. При успешной установке, но неудачной `verify`, оставлять `prepared` и разбирать причины проверки; не переключать `awg_main`.
