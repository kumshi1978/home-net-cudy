# HOME NET v1.7.20 — восстановление подготовленной VPN-транзакции через существующий LuCI

## Назначение
На основном квартирном Cudy работает `awg_main`, а `awg_backup` подготовлен для нового VDS. Транзакция `1d40d2f70e92f42d9bfa87c2967a525a` находится в фазе `prepared`, поскольку старый контроллер проверял advisory GeoIP `US`. V1.7.19 требовал только SSH; установленный LuCI использует старый updater, который не пересылает новые opt-in переменные.

## Изменение
- В **v1.7.20** существующая подтверждающая кнопка HOME NET → Updates → Install latest release поддерживает одноразовый путь восстановления для `prepared`.
- Обязательно совпадение **точно** `HOME_NET_CONFIRMED_RELEASE=v1.7.20`, переданное фоновым worker LuCI, `HOME_NET_MANAGEMENT_CONTEXT=1` и `HOME_NET_UPDATE_IN_PROGRESS=1`. Ручной путь через SSH из v1.7.19 сохранён.
- Автоматический запуск, отсутствие подтверждения релиза, неверный release tag, смешанные SSH/LuCI аргументы и неподходящий ID транзакции закрываются отказом.
- ID читается из текущей транзакции *только после явного подтверждения v1.7.20*; он не передаётся через браузер в старой версии LuCI. Установщик проверяет формат ID и целевой объект, а native-проверка повторно сверяет boot-id, исходный `awg_main`, подготовленный `awg_backup`, неизменный отпечаток `awg showconf`.
- Разрешён **только native-only upgrade** на pinned native agent 1.7.18. Никаких изменений Failover, Monitoring, Podkop, updater, key material, маршрутов или phase. Установщик не вызывает `verify` или `accept`.
- Новый пакет HOME NET — `1.7.20`, но *пакетное обновление в режиме восстановления частичное*: полный реинсталл других модулей может потребоваться отдельно после закрытия VPN-транзакции. Отображаемый номер bundle не доказывает, что все компоненты обновились.

## Ручная аппаратная проверка
1. Перед LuCI убедиться: `/usr/bin/home-net-vpn-router status` → `prepared`, deployment-id → `1d40d2f70e92f42d9bfa87c2967a525a`, boot-id совпадает, Podkop использует `awg_main`, endpoint `awg_backup` → `83.141.77.226:4333`, fingerprint `MATCH`, `home-net-install-verify services` → код 0. Не перезагружать до завершения.
2. В HOME NET → Updates нажать **Check for update**, убедиться в цели `v1.7.20` и классе `CONTROLLED`. Нажать **Install latest release**, прочитать и подтвердить.
3. Дождаться завершения задания, проверить `/usr/sbin/vpn-control-cudy version` → `1.7.18`, `/usr/bin/home-net-vpn-router status` → `prepared`, `uci -q get podkop.main.interface` → `awg_main`. При ошибке взять конкретный приватный журнал LuCI `/root/home-net-luci-install-*.log`. Не повторять наугад и не перезагружать.
4. Только после успешного upgrade отдельно выполнить `/usr/bin/home-net-vpn-router verify`; убедиться `verified`, затем через центральную панель принять существующую транзакцию `accept_verified`. Повторно проверить `completed/<deployment-id>/phase=accepted`, endpoint и активный `awg_main`.
5. После закрытия транзакции определить необходимость повторной штатной установки остального bundle, сверив точные версии компонентов; не предполагать, что native-only проход обновил их.

## Автоматизация и безопасность
Rollout остаётся `manual`. AutoApply из ветки `main` для этой версии не разрешён, а LuCI делает одноразовое подтверждение целевого релиза. Отдельный ID-контрол пока не появляется в старом интерфейсе — это совместимый безопасный переходный режим. Приватные ключи не передаются в LuCI и не пишутся в лог.

## Тесты
`tests/test-prepared-recovery-bundle.sh` проверяет две ручные цепочки (SSH и legacy LuCI) и отказ без opt-in, с другой версией, при `automatic_context`, а также смешанный контекст. Тест подтверждает вызов только native preflight/install и сохранение phase. Native `test-install.sh` отдельно отклоняет изменённый boot, candidate SHA, ID и несанкционированный active VPN. CI HOME NET включает все 22 suites.

## Откат
Пакет native сохраняет приватную резервную копию заменяемого исполняемого кода и восстанавливает его при ошибке. Если `verify` не сработает, оставить `prepared` для отдельной диагностики; не удалять transaction и не делать переключение/rollback без анализа журнала.
