# HOME NET Control: автоматическое появление роутера

С 1.7.6 обычная установка HOME NET также устанавливает исходящий агент панели.
Пакет агента находится в `control-agent/`, источник закреплён полным commit SHA;
установщик и оба исполняемых файла проверяются по SHA256. Доступ к закрытому
репозиторию панели или учётная запись GitHub на роутере не требуются.

Новый агент создаёт локальную age-identity, автоматически регистрируется на
`https://ui-control.kumshi.ru` через физический WAN и появляется в разделе
«Роутеры → Новые устройства». Доставка выключена до разрешения администратора.
Для активации в панели выбираются свободная роль и VDS. Ключ передаётся
автоматически; приватный ключ остаётся на роутере. Страна проверки определяется
по VDS, повторно вводить её не нужно.

На установленной 1.7.4/1.7.5/1.7.6 обновляются только политика SSH и агент;
проверенные Failover/Monitoring остаются прежних версий. Конфигурация агента,
AWG, Podkop и рабочие маршруты сохраняются. Установка требует Python3 с SSL,
age и age-keygen; отсутствующие зависимости ставятся через apk/opkg.
Для автономной Legacy-установки без панели предусмотрен явный отказ:
`HOME_NET_CONTROL_AUTOREGISTER=0`. По умолчанию агент устанавливается.

Установка агента не создаёт AWG-слоты и не обходит аппаратные проверки.
Разрешение доставки не равно готовности применения: контроллер, адаптер,
два корректных слота, свежая телеметрия и отсутствие незавершённой транзакции
проверяются отдельно. При проблеме панель блокирует доставку и показывает причину.
Применение профиля затрагивает только неактивный слот. Активация устройства
сама по себе не запускает отправку конфигурации или переключение маршрута.

Старые вручную подключённые агенты сохраняют свои учётные данные. Служба
`vpn-control-cudy` включается в автозапуск procd и опрашивает панель раз в минуту.
Первый этап выпуска — только кольцо canary. Дачные устройства остаются вне
аппаратной проверки до восстановления доступа.
