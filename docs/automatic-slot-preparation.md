# Автоматическая подготовка AWG-слотов

Сначала агент регистрируется в панели и передаёт состояние. До явного разрешения администратора создание интерфейсов запрещено: подготовка без роли ничего не записывает в network и не генерирует ключи. Локальный router-id сам по себе не является разрешением.

В панели администратор назначает место и роль, выбирает VDS и отдельно разрешает создание AWG-интерфейсов. Агент получает разрешение только со свежим успешным HTTPS-ответом панели, затем создаёт только отсутствующие awg_main и awg_backup: локальные ключи, proto=amneziawg, auto=0, без default route и peer DNS. Сеть не перечитывается, интерфейсы не включаются, Podkop не переключается. Без связи с панелью новое создание не выполняется; текущие соединения продолжают работать.

После назначения роли подготовленным отключённым интерфейсам назначаются
зарезервированные пары `10.8.1.201/32`–`10.8.1.208/32`: дом основной — 201/202,
дом резервный — 203/204, дача основной — 205/206, дача резервный — 207/208.
На VDS доступность конкретного peer-адреса проверяется отдельно при выдаче
конфига: локальная подготовка не резервирует адрес на удалённом VDS.

Существующие интерфейсы, ключи и адреса сохраняются. Имена, занятые другим
типом интерфейса или устройством ядра, не переиспользуются. Для назначения
адреса подготовленный интерфейс должен быть отключён, без peer и без IP.
Дубли адресов и пересечения с работающими локальными сетями блокируют запись.
Неподготовленный протокол AmneziaWG также блокирует подготовку; установщик
не подменяет модуль ядра для неизвестной сборки OpenWrt.

Используется общий maintenance lock. Незавершённая транзакция, несохранённые
изменения UCI и изменение файла сети во время подготовки запрещают запись.
Сначала UCI собирает конфигурацию в приватном staging-каталоге. Исходный
network сохраняется в root-only backup, новый файл заменяется атомарно.
Ключи передаются UCI на stdin и не выводятся в аргументы команд или журнал.
Повторная проверка не меняет уже подготовленную конфигурацию и не перезаписывает
статус во flash, если его смысл не изменился.

Панель показывает состояния «ожидает разрешения панели», «слоты подготовлены»
или конкретную причину остановки. Это статус локальной подготовки, а не
подтверждение первого подключения VPN. Первый профиль на полностью новом
роутере и фактический handshake требуют отдельной проверки bootstrap-доставки.

Проверка: полный набор Linux unit-тестов; создание и повторная проверка через
настоящий UCI в отдельном файле на резервном Cudy (отсутствие kernel-интерфейсов
имитируется, поскольку реальные имена заняты); установка на действующий
резервный Cudy с подтверждённой неизменностью network/Podkop/agent-конфигурации
и PID процессов VPN. Действующие интерфейсы при проверке не удаляются.
